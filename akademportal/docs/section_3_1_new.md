### 3.1 Платформаны іске асырудың негізгі кезеңдері

Visual Studio Code — веб-қосымшаларды әзірлеуге арналған кең таралған, икемді және кеңейтілетін код редакторы. Ол Microsoft тарапынан дамытылып, frontend және backend бағыттарында жұмыс істейтін әзірлеушілерге бір ортада толық циклді әзірлеу жүргізуге мүмкіндік береді. Дипломдық жоба аясында дәл осы орта қолданылды, себебі ол жеңіл, жылдам және плагиндік экожүйесі арқылы нақты жоба талаптарына тез бейімделеді. Visual Studio Code ортасының практикалық артықшылығы — оны тек «мәтін теретін редактор» ретінде емес, толыққанды инженерлік жұмыс кеңістігі ретінде қолдануға болатынында. Терминал, Git басқаруы, қате диагностикасы, код автотолтыру, рефакторинг, дебаг және live preview секілді құралдар бір интерфейсте шоғырланады. Бұл жоба барысында контекст ауыстыру санын азайтып, әзірлеу жылдамдығын айтарлықтай арттырды. (Сурет 31)

Жобаны жүзеге асыру бірнеше кезеңге бөлінді.

1-кезең. Жоба архитектурасын дайындау және орта конфигурациясы.

Алғашқы кезеңде әзірлеу ортасын дайындау жүргізілді. Бұл кезеңнің маңыздылығы — әзірлеу процесінің біртінді және қателерсіз жүруі үшін негіз құру. Node.js 18+ және npm/pnpm орнатылды — Node.js 18 LTS нұсқасы таңдалды, себебі ол тұрақты және қауіпсіз. PostgreSQL дерекқоры 16 нұсқасы localhost:5432 мекенжайында pgAdmin 4 басқару құралымен бапталды. Elasticsearch 8.15 Docker контейнерінде localhost:9200 мекенжайында works индексімен іске қосылды. Next.js 14 жобасы TypeScript шаблонымен, Tailwind CSS қосылып, App Router қолданылып, ESLint + Prettier бапталды. Prisma ORM бапталып, schema.prisma файлында 12 модель сипатталды, prisma migrate dev арқылы бастапқы миграция жасалды. Git репозиторийі құрылып, pre-commit hook (lint-staged + husky) және Vercel-мен автоматты орналастыру бапталды. Дерекқор схемасы Prisma Migrate арқылы жасалды: User, Work, Review, Faculty, Department, Keyword, Bookmark, BookmarkFolder, Download, Notification, SiteSettings, AuditLog модельдері өзара қатынастармен байланыстырылды. (Сурет 32)

2-кезең. Аутентификация және рөлдік жүйені іске қосу.

Екінші кезеңде пайдаланушы тіркелуі, кіруі және рөлдік қолжетімділік жүйесі іске асырылды. Бұл кезең платформаның қауіпсіздігінің негізін құрайды — аутентификация мен авторизация жүйесі дұрыс жұмыс істемесе, барлық басқа функциялардың қауіпсіздігі жоққа шығарылады. NextAuth.js Credentials провайдері бапталып, authorize функциясы арқылы эл. пошта және құпия сөз тексеріледі. JWT стратегиясы 7 күндік жарамдылық мерзімімен бапталды, рөлді токенге және сессияға қосу callbacks арқылы жүзеге асырылды. Тіркелу API-сы жасалды: студенттер автоматты мақұлданады, ғылыми жетекшілер күтудегі күйге қойылады, әкімші мақұлдағаннан кейін ғана кіре алады. Құпия сөздер bcryptjs арқылы 12 salt roundsпен хэштеледі. Middleware арқылы рөлді тексеру жүзеге асырылды: студент тек өз беттеріне, ғылыми жетекші — өз бөліміне, әкімші — барлық жүйеге қолжетімділік алады. (Сурет 33)

3-кезең. Жұмыстарды жүктеу жүйесін іске қосу.

Үшінші кезеңде студенттердің жұмыстарды жүктеу процесі іске асырылды. Бұл — платформаның негізгі функциясы, оның қарапайымдылығы, қауіпсіздігі және толықтығы маңызды. Үш қадамды жүктеу шебері жасалды: алғашқы қадамда файл таңдау (drag-and-drop zone, MIME-түр және өлшем тексеру, 25 МБ шектеу), екінші қадамда метадеректер енгізу (тақырып, аннотация, түр, жыл, тіл, кафедра, ғылыми жетекші, кілтті сөздер), үшінші қадамда растау. Файлдың MIME-түрі мен сиқырлы байттары тексеріледі — PDF үшін %PDF- префиксі, DOCX үшін PK\x03\x04 сигнатурасы. Файл дерекқорда PostgreSQL bytea типінде сақталады, PDF беттер саны pdf-parse арқылы автоматты есептеледі. Жұмыс күйі PENDING ретінде орнатылады, ғылыми жетекшіге ішкі хабарлама және эл. пошта жіберіледі. iThenticate API кілті болса плагиат тексеру жүргізіледі, жоқ болса null мәні қойылып, жұмыс процесі тоқтатылмайды.

4-кезең. Пікірлеме жүйесін іске қосу.

Төртінші кезеңде пікірлеме процесі іске асырылды. Бұл платформаның ең маңызды функцияларының бірі — пікірлеме процесінің сапасы жоғары оқу орнындағы білім беру сапасының тікелей көрсеткіші. Көпкритерийлі бағалау формасы жасалды: 4 критерий (өзектілігі, әдістеме, пішіндеу, қорытынды), 1-5 жұлдызшалық шкала, жалпы бағаның автоматты есептелуі. Пікірлеме шешімі: мақұлдау (APPROVE), қайтару (RETURN), қабылдамау (REJECT). Қайтару және қабылдамау кезінде себеп жазу міндетті. Пікірлеме жазылғаннан кейін жұмыс күйі автоматты өзгертіледі, авторға хабарлама жіберіледі, мақұлданған жұмыстар Elasticsearch индексіне қосылады. Бұқаралық пікірлеме мүмкіндігі жасалды — ғылыми жетекші бірнеше жұмысты таңдап, үлгі мәтінмен мақұлдау немесе қайтару жасай алады. Пікірлемені «пайдалы» деп белгілеу мүмкіндігі енгізілді. (Сурет 34)

5-кезең. Іздестіру жүйесін іске қосу.

Бесінші кезеңде іздестіру жүйесі іске асырылды. Іздестіру жүйесі — платформаның ақпараттық қолжетімділігінің негізі, оның тиімділігі пайдаланушылардың қажетті жұмыстарды табу жылдамдығын анықтайды. Elasticsearch works индексі құрылды: тақырып (3x boost), аннотация, кілтті сөздер, түр, факультет, кафедра, жыл, тіл, жетекші, күй, күні, көзқарас саны, жүктеме саны, жалпы баға өрістерімен. Multi_match сұрауы fuzziness:AUTO параметрімен терілу қателерін ескереді. Фасеттік сүзгілеу (түр, факультет, жыл, тіл, кафедра, жетекші бойынша) және агрегациялар жүзеге асырылды. Бөлектеу (highlighting) тақырып, аннотация және кілтті сөздерде <em> тегтерімен жасалады. Пагинация әр бетте 12 нәтиже көрсетеді. Elasticsearch қолжетімді болмаған жағдайда Prisma негізіндегі резервтік іздестіру қолданылады.

6-кезең. Әкімшілік панелін іске қосу.

Алтыншы кезеңде әкімшілік басқару жүйесі іске асырылды. Әкімшілік панелі — платформаны басқарудың, бақылаудың және есеп берудің негізгі құралы. Әкімші басты беті 4 KPI картасынан, факультеттер бойынша столбикті диаграммадан, жұмыс түрлерінің дөңгелек диаграммасынан, 30 күндік белсенділік графигінен және күтудегі жұмыстар кестесінен тұрады. Ғылыми жетекшілерді мақұлдау/қабылдамау интерфейсі жасалды: PENDING күйіндегі пайдаланушылар тізімі, мақұлдау немесе қабылдамау батырмалары, қабылдамау кезінде міндетті ескерту модалы. Факультеттер мен кафедраларды CRUD басқару, пайдаланушыларды басқару (рөлін өзгерту, жабу, жұмсақ жою), жұмыстарды модерациялау (модерациялық белгі қою/алу), жүйе параметрлерін басқару және аудит логтарын қарау функциялары енгізілді. Әрбір әкімшілік әрекет аудит логына жазылады. (Сурет 35)

7-кезең. Қосымша функциялар және сынау.

Жетінші кезеңде қосымша функциялар іске асырылды және жүйелі сынау жүргізілді. Жұмыстарды бөлектеу (bookmarks) және қалталарға бөлу мүмкіндігі жасалды. Мақұлданған жұмыстарды PDF/DOCX түрінде жүктеу, PDF алдын ала қарау, ұсынылатын жұмыстар, пайдаланушы профилін басқару, хабарлама жүйесі (ішкі хабарламалар + эл. пошта), көзқарас санын есептеу және жұмыс күйін бақылау функциялары енгізілді. Функционалдық сынау жүргізілді: әрбір API жолын тексеру, формаларды валидациялау, қате жағдайларды тексеру (401, 403, 404, 500). Қауіпсіздік сынау: CSRF, XSS, SQL инъекция, сұрау жиілігін шектеу. Пайдаланушы сынауы: 20 мақсатты пайдаланушымен сынақ сессиялары жүргізілді, SUS бағалауы 78 балды құрады. (Сурет 36)

Сонымен қатар, Visual Studio Code Git сияқты нұсқаларды басқару жүйелерімен терең интеграцияны қамтамасыз етеді, бұл оны жобалар бойынша жеке де, топтық та ынтымақтастыққа ыңғайлы ортаға айналдырады. Source Control панелі арқылы өзгерістерді кезең-кезеңімен бақылау, commit жасау, branch-пен жұмыс істеу және merge алдындағы айырмашылықтарды талдау жеңіл орындалады. IDE-нің плагин жүйесі функционалды едәуір кеңейтеді: ESLint, Prettier, GitLens, REST Client, Tailwind IntelliSense, Prisma құралдары және басқа да кеңейтімдер арқылы нақты әзірлеу міндеттеріне бейімделген жұмыс процесін құруға мүмкіндік береді. Visual Studio Code экожүйесінің маңызды артықшылығы — әзірлеушілер қауымдастығының жоғары белсенділігі және құралдың тұрақты жаңартылып отыруы. Бұл веб-индустриядағы өзгерістерге жедел бейімделуге жағдай жасайды: жаңа JavaScript/TypeScript мүмкіндіктері, framework-пен үйлесімділік, дебаг және өнімділік талдауы бойынша жақсартулар үздіксіз енгізіледі. Осындай үздіксіз эволюция нәтижесінде Visual Studio Code қазіргі заманғы веб-қосымшаларды құруға арналған жетекші инженерлік орталардың бірі ретінде орнықты.

Веб-қосымшаны жүзеге асыруда негізгі бағдарламалау негізі ретінде JavaScript/TypeScript тілі қолданылды. Бұл таңдау платформаның икемділігімен, экожүйесінің кеңдігімен және frontend пен backend-ті бір тілдік стекпен дамытуға болатындығымен түсіндіріледі. TypeScript қатаң типтеу арқылы API контракты, компонент пропстары, дерек құрылымдары және асинхронды логика деңгейінде қателерді ерте анықтауға көмектесті. Нәтижесінде, ірі UI күйімен және серверлік жауаптармен жұмыс істеу сенімді әрі болжамды болды. TypeScript тіліндегі қатаң типтік тексеріс орындау уақытындағы көптеген жиі қателердің алдын алады: undefined/null өңдеу, өріс атауларындағы сәйкессіздік, функция параметрлерінің қате берілуі, қате форматтағы payload жіберу сияқты мәселелер компиляция кезеңінде-ақ анықталады. Бұл тәсіл жобаның тұрақтылығын арттырып қана қоймай, кейінгі сүйемелдеуді де жеңілдетеді. Әсіресе командамен жұмыс істегенде типтік келісімдердің болуы жаңа әзірлеушінің код базасына тез бейімделуіне ықпал етеді.

JavaScript/TypeScript экожүйесінің негізгі артықшылықтарының бірі — кросс-платформалық сипат. Бір код базасы арқылы әртүрлі операциялық жүйеде (Windows, Linux, macOS) әзірлеу ортасын бірдей жүргізуге болады, ал браузерлік стандарттар веб-қосымшаның әртүрлі құрылғыларда (десктоп, планшет, мобильді браузер) жұмыс істеуін қамтамасыз етеді [19].

Веб-даму контекстінде таңдалған стек (Next.js, TypeScript, PostgreSQL, Prisma ORM, Elasticsearch, NextAuth.js) күрделі функционалдарды кезеңдеп енгізуге жеткілікті мүмкіндік берді. Next.js App Router архитектурасы серверлік компоненттер мен API маршруттарын біріктіруге, React компоненттік архитектурасы интерфейсті модульдеуге, PostgreSQL мен Prisma ORM деректерді тип қауіпсіздігімен басқаруға, Elasticsearch толық мәтінді іздеуді жүзеге асыруға жағдай жасады. API қабаты арқылы жұмыс жүктеу, пікірлеме жүргізу, іздестіру, хабарлама жіберу және әкімші басқаруы бір жүйеге біріктірілді.

TypeScript пен JavaScript қолдану жобаға сенімділік, масштабталу және қызмет көрсету ыңғайлылығы сияқты практикалық артықшылықтар берді. Асинхронды өңдеуді тиімді ұйымдастыру (async/await), желілік сұраулармен жұмыс, күй басқару және модульдік архитектураны сақтау веб-қолданбаның сапалы дамуына негіз болды. Сонымен бірге, әлемдік ашық қауымдастық пен дайын кітапханалардың молдығы (UI компоненттер, валидация, қауіпсіздік, интернационализация, графиктер) әзірлеу процесін айтарлықтай байытты.

Қорытындылай келе, Visual Studio Code пен TypeScript/JavaScript үйлесімі Task IN жобасын жүзеге асыру үшін оңтайлы технологиялық платформа болды. Бұл комбинация академиялық жұмыстарды басқару процесін цифрлық форматта қолдайтын, қолжетімділігі жоғары, функционалды және кеңейтуге бейім веб-қосымша құруға қажетті барлық инженерлік ресурсты қамтамасыз етті. Яғни таңдалған технологиялық шешімдер тек ағымдағы міндеттерді орындап қана қоймай, жүйені болашақта өндірістік деңгейге дамытуға да берік негіз қалады. Әсіресе академиялық платформа сияқты көп модульді жүйеде (Auth, Works, Reviews, Search, Admin) контекст ауыстырудың азаюы инженерлік өнімділікті айтарлықтай арттырды. Келесі подтарауда платформаның дерекқормен және сыртқы API-мен әрекеттесу механизмдері қарастырылады.
