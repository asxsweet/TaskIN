# Студенттердің академиялық жұмыстарын орталықтандырылған сақтау және іздеуге арналған веб-порталды жобалау және іске асыру

*Дипломдық жобаның есептік түсініктемелік жазбасына арналған мәтіндік нұсқа. Құжат Word форматына көшірілген кезде мазмұндағы бет нөмірлері, сурет/кесте атаулары және қосымшалар оқу орнының талаптарына сәйкес нақтыланады.*

---

## Жұмыстың бастапқы берілістері

Дипломдық жобаны орындау барысында төмендегі бастапқы деректер, әдістемелік материалдар және бағдарламалық құралдар негізге алынды.

**1) Әдістемелік негіз** - жоғары оқу орнының дипломдық жобаны орындау және қорғау ережелері, кафедра бекіткен тақырып, ғылыми жетекшінің ұсынымдары, бағдарламалық жүйені жобалау мен іске асыруға қойылатын жалпы талаптар. Жобаның тақырыбы: **"Студенттердің академиялық жұмыстарын орталықтандырылған сақтау және іздеуге арналған веб-порталды жобалау және іске асыру"**.

**2) Ақпараттық жабдықтау** - академиялық жұмыстарды электронды түрде сақтау, цифрлық репозиторийлер, веб-порталдар, рөлдік қолжетімділік, іздеу жүйелері, дерекқор жобалау, файлдарды сақтау, ақпараттық қауіпсіздік және пайдаланушы интерфейсін жобалау тақырыптарындағы оқулықтар, ғылыми мақалалар, ресми құжаттамалар және веб-технологиялар бойынша тәжірибелік материалдар. Жобаның нақты коды мен құжаттамасы **Task IN / akademportal** репозиторийінде жинақталған.

**3) Бағдарламалық құралдар** - **Node.js 20+**, **npm**, **Git**, **Docker Desktop**; клиенттік және серверлік бөлік үшін **Next.js 14**, **React 18**, **TypeScript**, **Tailwind CSS**; деректер қабаты үшін **PostgreSQL**, **Prisma ORM**; аутентификация үшін **NextAuth**, парольдерді қорғау үшін **bcryptjs**; валидация үшін **Zod**; іздеу үшін **Elasticsearch** және PostgreSQL fallback; файлдарды өңдеу үшін **pdf-parse**; хабарлама және пошта интеграциялары үшін **nodemailer**; UI элементтері үшін **lucide-react**, **framer-motion** және жобаның ішкі компоненттері қолданылды.

**4) Техникалық құралдар** - жобаны әзірлеу және сынау үшін жеке компьютер, кемінде 8 ГБ жедел жад, SSD/HDD сақтау орны, Microsoft Windows 10/11 немесе Linux/macOS операциялық жүйесі, интернет қосылымы, Google Chrome, Microsoft Edge немесе Mozilla Firefox браузері. Жергілікті ортада PostgreSQL және Elasticsearch Docker арқылы іске қосылады, ал production ортаға Vercel немесе Render арқылы орналастыру қарастырылған.

## Есептік түсініктемелік жазба мазмұны

Дипломдық жобада студенттердің академиялық жұмыстарын бір ортада жинау, тексеру, іздеу және басқару мәселесі қарастырылады. Жоба оқу орны ішінде дипломдық жұмыстар, курстық жұмыстар, мақалалар, эсселер және жобалық жұмыстар сияқты материалдарды реттелген түрде сақтауға арналған веб-портал ретінде сипатталады.

1. **Академиялық жұмыстарды цифрлық сақтау және іздеу жүйелеріне шолу** - электронды репозиторийлердің маңызы, оқу орнындағы құжат айналымы, іздеу және қолжетімділік мәселелері.
2. **Веб-порталды жобалау** - функционалдық талаптар, пайдаланушы рөлдері, интерфейс құрылымы, технологиялар стегі, дерекқор моделі және жүйелік архитектура.
3. **Веб-порталдың іске асырылған мүмкіндіктеріне шолу** - студент, жетекші және әкімші сценарийлері, файл жүктеу, рецензиялау, іздеу, хабарлама, bookmark, есеп беру және қауіпсіздік механизмдері.
4. **Еңбекті қорғау және өміртіршілік қауіпсіздігі** - бағдарламашының жұмыс орны, электр қауіпсіздігі, жарықтандыру, микроклимат және өрт қауіпсіздігі.
5. **Қорытынды** - алынған нәтижелер, жобаның практикалық маңызы және болашақта дамыту бағыттары.
6. **Пайдаланылған әдебиеттер тізімі және қосымшалар** - ресми құжаттамалар, ғылыми дереккөздер, бағдарламалық код үзінділері және интерфейс материалдары.

## Аңдатпа

**Қазақ тілінде.** Зерттеу нысаны - студенттердің академиялық жұмыстарын орталықтандырылған түрде сақтау, іздеу, тексеру және басқаруға арналған веб-портал. Жоба шартты түрде **Task IN** деп аталады. Қазіргі оқу процесінде студенттердің дипломдық жұмыстары, курстық жұмыстары, мақалалары және басқа академиялық материалдары көбіне әртүрлі файлдарда, поштада немесе жеке құрылғыларда сақталады. Мұндай тәсіл материалдарды іздеуді, жетекші тарапынан тексеруді, әкімшілік бақылауды және кейін қайта пайдалануды қиындатады. Сондықтан академиялық жұмыстарды бірыңғай дерекқорда сақтау, оларды метадеректер бойынша іздеу және рөлдер арқылы басқару өзекті мәселе болып табылады.

Жұмыстың мақсаты - студент, жетекші және әкімші рөлдері бар, академиялық жұмыстарды жүктеуге, сақтауға, іздеуге, рецензиялауға және модерациялауға мүмкіндік беретін веб-порталды жобалау және іске асыру. Жүйе **Next.js**, **React**, **TypeScript**, **Prisma ORM**, **PostgreSQL**, **NextAuth**, **Tailwind CSS** технологиялары негізінде әзірленді. Іздеу мүмкіндігі үшін **Elasticsearch** қолдауымен бірге PostgreSQL fallback механизмі қарастырылған. Файлдар PostgreSQL дерекқорында сақталады, ал PDF құжаттар бойынша бет саны анықталады. Нәтижесінде оқу орнының академиялық материалдарын басқаруға арналған толық стекті веб-портал прототипі алынды.

**Кілт сөздер:** академиялық жұмыс, веб-портал, орталықтандырылған сақтау, іздеу жүйесі, Next.js, PostgreSQL, Prisma, Elasticsearch, рөлдік қолжетімділік.

**Орыс тілінде.** Объектом исследования является веб-портал для централизованного хранения, поиска, проверки и управления академическими работами студентов. Актуальность темы связана с тем, что дипломные, курсовые и проектные работы часто хранятся разрозненно: в личных папках, электронной почте или отдельных носителях. Это усложняет поиск, контроль, рецензирование и повторное использование материалов. Цель работы - разработать веб-портал с ролями студента, научного руководителя и администратора, обеспечивающий загрузку, хранение, поиск, рецензирование и модерацию академических работ.

Система реализована на основе **Next.js**, **React**, **TypeScript**, **Prisma ORM**, **PostgreSQL**, **NextAuth** и **Tailwind CSS**. Для расширенного поиска предусмотрена интеграция с **Elasticsearch**, а при его отсутствии используется поиск средствами PostgreSQL. Файлы сохраняются непосредственно в базе данных, что упрощает локальное развертывание прототипа. Результатом является работоспособный прототип полнофункционального веб-портала для управления академическими работами в учебном заведении.

**Ключевые слова:** академическая работа, веб-портал, централизованное хранение, поисковая система, Next.js, PostgreSQL, Prisma, Elasticsearch, ролевая модель.

**In English.** *Design and implementation of a web portal for centralized storage and search of students' academic works.* The research object is a web portal that stores, searches, reviews and manages students' academic materials in a single digital environment. The system supports student, supervisor and administrator roles, file upload, metadata management, review workflow, moderation, bookmarks, notifications and search. The project is implemented with **Next.js**, **React**, **TypeScript**, **Prisma ORM**, **PostgreSQL**, **NextAuth** and **Tailwind CSS**. Search is supported by **Elasticsearch** with a PostgreSQL fallback. The result is a functional full-stack prototype suitable for academic repository scenarios in educational institutions.

**Keywords:** academic work, web portal, centralized storage, search system, Next.js, PostgreSQL, Prisma, Elasticsearch, role-based access.

# Кіріспе

## Зерттеудің өзектілігі

Жоғары оқу орындарында студенттердің академиялық жұмыстары оқу процесінің маңызды нәтижесі болып табылады. Дипломдық жобалар, курстық жұмыстар, ғылыми мақалалар, эсселер және жобалық тапсырмалар студенттің зерттеу дағдысын, пәндік білімін және практикалық қабілетін көрсетеді. Алайда бұл жұмыстардың көп бөлігі ұзақ уақыт бойы әртүрлі тасымалдағыштарда, пошта хаттарында, мессенджерлерде немесе жеке компьютерлерде сақталып келеді. Мұндай бытыраңқы сақтау тәсілі материалдардың жоғалуына, қайталануына, іздеудің күрделенуіне және оқу орны деңгейінде білім қорын қалыптастырудың қиындауына әкеледі.

Орталықтандырылған веб-портал бұл мәселені жүйелік түрде шешеді. Біріншіден, барлық академиялық жұмыс бір дерекқорда сақталады және оған автор, факультет, кафедра, жетекші, жыл, жұмыс түрі, тіл және кілт сөздер сияқты метадеректер тіркеледі. Екіншіден, іздеу және сүзгілеу арқылы қажетті жұмысты тез табуға болады. Үшіншіден, жетекші мен әкімші рөлдері арқылы тексеру, рецензиялау, бекіту және модерациялау процестері реттеледі. Төртіншіден, студенттер үшін өз жұмыстарын жүктеу, статусын бақылау және кейін қайта қарау мүмкіндігі пайда болады.

Ақпараттық жүйе тұрғысынан бұл жоба бірнеше маңызды міндетті біріктіреді: пайдаланушыны аутентификациялау, рөлдік құқықтарды басқару, файлдарды қауіпсіз қабылдау, деректерді валидациялау, іздеу индексін жүргізу, хабарламалар жіберу және интерфейсті әртүрлі құрылғыға бейімдеу. Сондықтан дипломдық жобаның өзектілігі тек нақты оқу орнының қажеттілігімен емес, сонымен қатар қазіргі цифрлық білім беру инфрақұрылымының даму бағытымен де байланысты.

## Жобаның атауы, нысаны, предметі және мақсаты

**Жобаның толық атауы:** "Студенттердің академиялық жұмыстарын орталықтандырылған сақтау және іздеуге арналған веб-порталды жобалау және іске асыру".

**Зерттеу нысаны:** студенттердің академиялық жұмыстарын электронды түрде сақтауға және басқаруға арналған веб-портал.

**Зерттеу предметі:** веб-порталдың функционалдық талаптары, рөлдік моделі, дерекқор құрылымы, іздеу механизмі, API архитектурасы, файл сақтау тәсілі және пайдаланушы интерфейсі.

**Жұмыстың мақсаты:** оқу орны ішінде студенттердің академиялық жұмыстарын бір орталық жүйеде сақтау, іздеу, тексеру және басқару мүмкіндігін беретін веб-порталдың архитектурасын жобалау және жұмыс істейтін прототипін іске асыру.

## Зерттеу міндеттері

1. Академиялық жұмыстарды цифрлық сақтау және іздеу жүйелерінің маңызын талдау.
2. Веб-порталға қойылатын функционалдық және функционалдық емес талаптарды анықтау.
3. Студент, жетекші және әкімші рөлдерінің негізгі сценарийлерін сипаттау.
4. Жүйенің архитектурасын, дерекқор моделін және API құрылымын жобалау.
5. Next.js, PostgreSQL, Prisma және Elasticsearch негізіндегі технологиялар стегін негіздеу.
6. Академиялық жұмыс жүктеу, сақтау, іздеу, рецензиялау және модерациялау функцияларын іске асыру.
7. Қауіпсіздік, валидация, файл шектеулері және рөлдік қолжетімділік механизмдерін сипаттау.
8. Жобаны жергілікті және production ортада іске қосу жолдарын көрсету.
9. Алынған нәтижелерді қорытындылап, болашақ дамыту бағыттарын ұсыну.

## Ғылыми жаңалығы мен практикалық маңызы

**Ғылыми жаңалығы** - академиялық жұмыстардың өмірлік циклін бір веб-портал ішінде модельдеу: студент жұмысты жүктейді, жетекші оны қарайды және шешім шығарады, әкімші жүйені бақылайды, ал бекітілген жұмыстар іздеу индексіне түсіп, оқу орнының цифрлық академиялық қорына айналады. Бұл тәсіл файл сақтауды ғана емес, тексеру, модерация, рейтинг, bookmark және хабарлама сияқты процестерді де бір жүйеге біріктіреді.

**Практикалық маңызы** - жоба оқу орны ішінде дипломдық және басқа академиялық жұмыстарды басқару жүйесінің прототипі ретінде қолдануға жарамды. Ашық технологиялар стегі жобаны әрі қарай кеңейтуге мүмкіндік береді: плагиат тексеру сервистерін толық қосу, файлдарды S3/MinIO сияқты object storage жүйесіне көшіру, іздеуді семантикалық деңгейге көтеру, аналитикалық есептерді кеңейту және институционалдық репозиторий ретінде дамыту.

# 1 Академиялық жұмыстарды орталықтандырылған сақтау және іздеу жүйелеріне шолу

## 1.1 Академиялық жұмыстарды цифрлық форматта сақтау қажеттілігі

Академиялық жұмыс - оқу процесінің нәтижесін көрсететін маңызды құжат. Оның ішінде студенттің зерттеу әдістемесі, әдебиеттермен жұмыс істеуі, практикалық шешімі және қорытынды ойлары жинақталады. Егер мұндай материалдар жүйесіз сақталса, олар кейінгі студенттерге, жетекшілерге және кафедраға пайдалы білім көзі ретінде қолданылмай қалады.

Цифрлық сақтау жүйесі осы мәселені шешуге бағытталады. Әр жұмысқа құрылымдық метадерек бекітіледі: атауы, аннотациясы, жұмыс түрі, жылы, тілі, авторы, факультеті, кафедрасы, жетекшісі, кілт сөздері және файл өлшемі. Мұндай метадеректер іздеуді жеңілдетіп қана қоймай, оқу орнының ғылыми-әдістемелік қорын талдауға да мүмкіндік береді.

Орталықтандырылған сақтау дерек тұтастығын арттырады. Жұмыс бір рет жүктеліп, оның статусы жүйе ішінде бақыланады: қаралуда, бекітілді, қайтарылды немесе қабылданбады. Бұл студент үшін де, жетекші үшін де түсінікті процесс қалыптастырады. Сонымен қатар әкімші барлық жұмыстарды жалпы тізімнен көріп, қажет жағдайда модерация жасай алады.

## 1.2 Орталықтандырылған репозиторий және веб-портал ұғымы

Орталықтандырылған репозиторий - белгілі бір ұйымның электронды материалдарын бір жерде сақтайтын ақпараттық жүйе. Академиялық ортада мұндай репозиторий дипломдық жұмыстарды, курстық жұмыстарды, ғылыми мақалаларды және жобалық материалдарды жүйелеуге арналған. Веб-портал осы репозиторийге браузер арқылы қол жеткізуді қамтамасыз етеді.

Task IN жобасында веб-портал үш негізгі пайдаланушы тобын қамтиды:

- **Студент** - тіркеледі, жеке кабинетке кіреді, академиялық жұмысын жүктейді, өз жұмыстарының статусын қарайды, бекітілген жұмыстарды іздейді, bookmark жасайды және хабарламаларды бақылайды.
- **Жетекші** - өзіне бекітілген студенттердің жұмыстарын қарайды, рецензия береді, балл қояды, жұмысты бекітеді, қайтарады немесе қабылдамайды.
- **Әкімші** - пайдаланушыларды, факультеттерді, кафедраларды, жұмыстарды, жетекші өтінімдерін, сайт баптауларын, есептерді және аудит жазбаларын басқарады.

Осы рөлдік модель порталдың нақты оқу процесіне жақын болуын қамтамасыз етеді. Әр рөл тек өзіне тиісті әрекеттерді орындайды, ал жүйе API деңгейінде рұқсатты тексереді.

## 1.3 Іздеу, сүзгілеу және қолжетімділік мәселелері

Академиялық жұмыстар саны көбейген сайын қарапайым тізім жеткіліксіз болады. Пайдаланушы белгілі бір тақырып, кілт сөз, жыл, факультет, кафедра, жұмыс түрі немесе тіл бойынша материал таба алуы керек. Сондықтан іздеу жүйесі порталдың негізгі функционалдық бөлігі болып есептеледі.

Жобада іздеу екі деңгейде ұйымдастырылған. Егер **Elasticsearch** қолжетімді болса, бекітілген жұмыстар арнайы индекске жазылады және атау, аннотация, кілт сөздер бойынша толық мәтіндік іздеу іске асады. Іздеу нәтижелері relevance, күн, жүктеу саны немесе рейтинг бойынша сұрыптала алады. Егер Elasticsearch орнатылмаған болса, жүйе PostgreSQL негізіндегі fallback іздеуді қолданады. Бұл шешім жобаның локал ортада да, production ортада да тұрақты жұмыс істеуіне көмектеседі.

Қолжетімділік мәселесі де маңызды. Портал ашық файл қоймасы емес, рөлдерге негізделген басқарылатын жүйе. Сондықтан студент тек өз әрекеттеріне және жалпы бекітілген жұмыстарға қол жеткізеді, жетекші өзіне тағайындалған жұмыстарды қарайды, ал әкімші толық басқару панелін қолданады. Мұндай шектеу деректердің қауіпсіздігін және оқу процесінің тәртібін сақтайды.

# 2 Веб-порталды жобалау және әзірлеу

## 2.1 Жүйеге қойылатын талаптар

Жүйеге қойылатын талаптар функционалдық және функционалдық емес болып бөлінеді.

**Функционалдық талаптар:**

1. Пайдаланушы тіркелу және жүйеге кіру мүмкіндігіне ие болуы керек.
2. Жүйеде студент, жетекші және әкімші рөлдері болуы тиіс.
3. Студент академиялық жұмыстың атауын, аннотациясын, түрін, жылын, тілін, кафедрасын, жетекшісін және кілт сөздерін енгізіп, файл жүктей алуы керек.
4. Жүйе PDF және DOCX файлдарын қабылдап, файл өлшеміне шектеу қоюы қажет.
5. Жетекші жұмысқа рецензия беріп, relevance, methodology, formatting және conclusion критерийлері бойынша баға қоя алуы керек.
6. Жұмыстың статусы PENDING, APPROVED, RETURNED немесе REJECTED күйінде сақталуы тиіс.
7. Бекітілген жұмыстар іздеу бетінде көрсетіліп, сүзгілеу және сұрыптау мүмкіндігі болуы керек.
8. Пайдаланушы қызықты жұмыстарды bookmark ретінде сақтай алуы тиіс.
9. Жүйе хабарламалар арқылы маңызды өзгерістерді пайдаланушыға жеткізуі керек.
10. Әкімші пайдаланушыларды, факультеттерді, кафедраларды, жұмыстарды, жетекші өтінімдерін және сайт баптауларын басқара алуы керек.

**Функционалдық емес талаптар:**

1. Интерфейс адаптивті болуы және desktop/mobile құрылғыларда ыңғайлы жұмыс істеуі керек.
2. Құпиясөздер ашық түрде сақталмай, хэш түрінде қорғалуы тиіс.
3. API endpoint-тері рөлдік құқықтарды тексеруі қажет.
4. Файл жүктеу кезінде MIME type, кеңейтім және файл сигнатурасы тексерілуі керек.
5. Дерекқор схемасы кеңейтуге ыңғайлы болуы тиіс.
6. Іздеу сервисі істемей қалған жағдайда жүйе толық тоқтамай, fallback режимде жұмыс істеуі керек.
7. Жоба локал ортада және hosting платформаларында іске қосыла алуы қажет.

## 2.2 Пайдаланушы рөлдері және негізгі сценарийлер

**Студент сценарийі** тіркелуден басталады. Студент факультетін таңдап, жүйеге кіреді. Жеке кабинетте статистикасын, хабарламаларын және өз жұмыстарының тізімін қарайды. Жұмыс жүктеу бетінде қажетті метадеректерді толтырып, PDF немесе DOCX файлын тіркейді. Жүктелген жұмыс бастапқыда PENDING статусына түседі. Кейін жетекші немесе әкімші шешіміне қарай жұмыс бекітіледі, қайтарылады немесе қабылданбайды.

**Жетекші сценарийі** өтінім арқылы іске қосылады. Жетекші тіркелген кезде кафедра, қызмет, телефон және қызметкер нөмірі сияқты қосымша ақпарат енгізеді. Әкімші жетекші өтінімін бекіткеннен кейін ғана ол жүйеге толық кіре алады. Жетекші өзіне тағайындалған жұмыстарды қарап, рецензия формасын толтырады. Рецензияда жұмыстың өзектілігі, әдістемесі, рәсімделуі және қорытындысы бағаланады. Сонымен бірге күшті жақтар, ұсыныстар, жалпы пікір және шешім жазылады.

**Әкімші сценарийі** жүйені басқаруға бағытталған. Әкімші dashboard арқылы жалпы статистиканы қарайды, пайдаланушыларды бұғаттайды немесе өңдейді, жетекші өтінімдерін бекітеді, факультет пен кафедра деректерін басқарады, жұмыстарды сүзгілейді, flagged материалдарды қарайды, есептер мен рейтингтерді бақылайды. Әкімші рөлі жүйенің сапасын және тәртібін сақтауға арналған.

## 2.3 Қолданылған технологиялар және таңдалу себебі

Жоба **Next.js 14** негізінде әзірленді. Бұл фреймворк React компоненттерін, серверлік API route-тарды, routing жүйесін және production build процесін бір ортада біріктіреді. Сондықтан бөлек frontend және backend жобаларын жүргізбей, толық стек веб-порталды бір кодбазада жасауға мүмкіндік береді.

**React 18** пайдаланушы интерфейсін компоненттерге бөліп құруға қолданылады. Жобада Button, Input, Select, Badge, Toast, Skeleton, EmptyState сияқты қайта қолданылатын UI компоненттері бар. Мұндай тәсіл интерфейстің бірізділігін сақтайды және жаңа беттерді тез құруға көмектеседі.

**TypeScript** кодтағы тип қауіпсіздігін арттырады. Пайдаланушы рөлі, жұмыс статусы, форма деректері және API жауаптары сияқты құрылымдарда типтің болуы қателерді ерте анықтауға көмектеседі.

**Prisma ORM** PostgreSQL дерекқорымен жұмыс істеуді жеңілдетеді. Prisma schema арқылы User, Work, Review, Faculty, Department, Keyword, Bookmark, Notification, AuditLog сияқты модельдер анықталған. Бұл модельдер жүйенің домендік логикасын нақты көрсетеді.

**PostgreSQL** негізгі дерекқор ретінде таңдалды, себебі ол реляциялық байланыстарды, транзакцияларды және күрделі сұрауларды тұрақты қолдайды. Жобада файл деректері де PostgreSQL ішінде Bytes өрісі арқылы сақталады. Прототип үшін бұл тәсіл deployment пен backup логикасын жеңілдетеді.

**Elasticsearch** толық мәтіндік іздеу сапасын арттыру үшін қосылған. Ол атау, аннотация және кілт сөздер бойынша relevance негізінде іздеуге, highlight және aggregation алуға мүмкіндік береді. Сонымен бірге жүйеде Elasticsearch жоқ ортаға арналған PostgreSQL fallback қарастырылған.

**NextAuth** пайдаланушы сессиясын JWT стратегиясы арқылы басқаруға қолданылады. CredentialsProvider email/password арқылы кіруді іске асырады, ал парольдер **bcryptjs** арқылы салыстырылады.

**Tailwind CSS** интерфейсті жылдам және бірізді стильдеуге мүмкіндік береді. Жоба жарық/қараңғы тақырыпты қолдайды және layout компоненттері арқылы desktop және mobile навигация ұйымдастырылады.

## 2.4 Архитектура, дерекқор моделі және API құрылымы

Жоба клиент-сервер архитектурасына негізделген, бірақ Next.js App Router арқылы бір репозиторийде ұйымдастырылған. Клиенттік беттер `app` каталогында орналасқан, ал серверлік endpoint-тер `app/api` ішінде берілген. Ортақ бизнес логика `lib` каталогына шығарылған.

Жүйенің негізгі қабаттары:

1. **UI қабаты** - студент, жетекші және әкімші беттері, layout, navigation, form және reusable component-тер.
2. **API қабаты** - auth, works, search, bookmarks, profile, admin, supervisor endpoint-тері.
3. **Қолданбалық логика қабаты** - authorization helper-лері, Elasticsearch интеграциясы, audit, security, validation, email және rate limit логикасы.
4. **Дерекқор қабаты** - Prisma Client арқылы PostgreSQL-мен әрекеттесу.
5. **Іздеу қабаты** - Elasticsearch индексі және fallback SQL search.

Дерекқордағы негізгі модельдер:

- **User** - пайдаланушының аты, email, password, role, faculty, department, profile, approval status және байланыс деректері.
- **Work** - академиялық жұмыстың атауы, аннотациясы, түрі, жылы, тілі, файлы, статусы, плагиат көрсеткіші, авторы, жетекшісі, кафедрасы және статистикасы.
- **Review** - жетекші берген бағалар, пікір, ұсыныс және шешім.
- **Faculty** және **Department** - оқу орнының құрылымдық бөлімдері.
- **Keyword** - жұмысқа тіркелген кілт сөздер.
- **Bookmark** және **BookmarkFolder** - пайдаланушы сақтаған жұмыстар және олардың папкалары.
- **Download** - жүктеу тарихы.
- **Notification** - пайдаланушыға жіберілетін хабарламалар.
- **AuditLog** - әкімшілік әрекеттердің аудит жазбалары.

API құрылымы порталдағы негізгі сценарийлерге сәйкес жасалған. Мысалы, `/api/works` endpoint-і жұмыс тізімін алу және жаңа жұмыс жүктеу үшін қолданылады; `/api/search` бекітілген жұмыстарды іздейді; `/api/bookmarks` bookmark әрекеттерін басқарады; `/api/admin/users`, `/api/admin/works`, `/api/admin/approvals` әкімші операцияларын іске асырады; `/api/supervisor/assigned` жетекшіге тағайындалған жұмыстарды көрсетеді.

# 3 Веб-порталдың мүмкіндіктеріне шолу

## 3.1 Студент кабинеті және академиялық жұмыс жүктеу

Студент кабинеті пайдаланушының жеке академиялық кеңістігі ретінде қарастырылады. Dashboard бетінде студент өз жұмыстарының жалпы күйін, соңғы хабарламаларды және негізгі әрекеттерді көре алады. "My works" бөлімі студент жүктеген жұмыстарды статусымен бірге көрсетеді. "Upload" бетінде жаңа академиялық жұмыс енгізіледі.

Жұмыс жүктеу кезінде жүйе бірнеше тексеріс жасайды. Файл міндетті түрде болуы керек, метадерек JSON форматында беріледі, файл өлшемі 25 MB-тан аспауы тиіс. Рұқсат етілген форматтар - PDF және DOCX. PDF үшін `%PDF-` сигнатурасы, DOCX үшін ZIP сигнатурасы тексеріледі. Бұл қауіпсіздік пен дерек сапасын арттырады, себебі қолданушы файл кеңейтімін қолдан өзгерткен жағдайда жүйе оны қабылдамайды.

PDF файл жүктелген кезде жүйе `pdf-parse` арқылы бет санын анықтауға тырысады. Жұмыс дерекқорға сақталғаннан кейін оның статусы PENDING болады. Егер жетекші таңдалса, жүйе жетекшіге тағайындау туралы хабарлама жібере алады. Кейін жұмыс бекітілген жағдайда Elasticsearch индексіне енгізіліп, жалпы іздеу нәтижелерінде пайда болады.

## 3.2 Жетекші кабинеті және рецензиялау процесі

Жетекші кабинеті академиялық жұмыстарды қарауға және бағалауға арналған. "Assigned" бетінде жетекшіге тағайындалған жұмыстар тізімі беріледі. Әр жұмысқа кірген кезде жетекші оның атауын, аннотациясын, авторын, кафедрасын, файл деректерін және басқа метадеректерін қарай алады.

Рецензия формасы бірнеше бағалау критерийінен тұрады: relevance, methodology, formatting және conclusion. Бұл критерийлер жұмыстың ғылыми өзектілігін, әдістемелік сапасын, рәсімделу деңгейін және қорытындысының толықтығын бағалауға мүмкіндік береді. Жетекші күшті жақтарын, ұсыныстарын, жалпы пікірін және шешімін жазады.

Шешім үш түрлі болуы мүмкін: APPROVE, RETURN немесе REJECT. APPROVE кезінде жұмыс бекітіліп, іздеу жүйесіне қосылады. RETURN кезінде студентке түзетуге қайтарылады және міндетті түрде қайтару себебі көрсетіледі. REJECT кезінде жұмыс қабылданбайды. Мұндай workflow жетекші мен студент арасындағы тексеру процесін жүйелендіреді.

## 3.3 Әкімші панелі, модерация және есеп беру

Әкімші панелі жүйенің басқару орталығы болып табылады. Admin dashboard арқылы әкімші жалпы статистиканы және негізгі көрсеткіштерді бақылайды. Пайдаланушылар бөлімі арқылы студенттерді, жетекшілерді және әкімшілерді көреді, қажет жағдайда деректерін өзгертеді немесе аккаунтты бұғаттайды.

Жетекші өтінімдері бөлек approvals бетінде қаралады. Жетекші тіркелген кезде оның аккаунты бірден толық белсенді болмайды; әкімші оны бекітуі керек. Бұл оқу орнының нақты кадрлық тәртібіне сәйкес келеді және кездейсоқ немесе жалған жетекші аккаунттарының жүйеге кіруін шектейді.

Works бөлімі барлық академиялық жұмыстарды status, faculty, year, type және flagged белгісі бойынша сүзгілеуге мүмкіндік береді. Әкімші күмәнді материалдарды белгілей алады, модерация жасайды және қажет жағдайда жұмысты басқару шешімін қабылдайды. Reports және ratings беттері жүйедегі белсенділік пен сапалық көрсеткіштерді талдауға арналған.

## 3.4 Іздеу жүйесі, bookmark және хабарламалар

Іздеу беті бекітілген академиялық жұмыстарды табуға арналған. Пайдаланушы тақырып немесе аннотация бойынша мәтін енгізе алады, жұмыс түрін, факультетті, жыл аралығын, тілді және кафедраны таңдай алады. Сұрыптау relevance, дата, жүктеу саны немесе рейтинг бойынша жүргізіледі.

Bookmark функциясы пайдаланушыға қызықты жұмыстарды жеке тізімге сақтауға мүмкіндік береді. Сонымен қатар bookmark folder механизмі арқылы сақталған жұмыстарды папкаларға бөлуге болады. Бұл әсіресе зерттеу тақырыбы бойынша бірнеше жұмысты жинап, кейін салыстыру үшін пайдалы.

Хабарламалар жүйесі пайдаланушыға маңызды өзгерістерді жеткізеді: жетекшіге жұмыс тағайындалуы, студент жұмысының статусы өзгеруі, әкімшілік шешімдер және басқа оқиғалар. NotificationBell және notifications беттері арқылы пайдаланушы оқылмаған хабарламаларды бақылай алады.

## 3.5 Қауіпсіздік, валидация және орналастыру

Қауіпсіздік жүйенің негізгі талаптарының бірі болып табылады. Пайдаланушы сессиясы NextAuth арқылы басқарылады, ал API деңгейінде `requireUser`, `requireAdmin`, `requireStudent`, `requireSupervisorOrAdmin` сияқты helper-лер қолданылады. Бұл endpoint-терге кездейсоқ қол жеткізуді шектейді.

Форма деректері Zod схемалары арқылы тексеріледі. Тіркелу кезінде email форматы, пароль ұзындығы, рөлге байланысты міндетті өрістер тексеріледі. Жұмыс жүктеу кезінде атау, аннотация, жұмыс түрі, жыл, тіл, кафедра және кілт сөздер валидациядан өтеді. Рецензия кезінде баға диапазоны және шешімге байланысты қайтару себебі тексеріледі.

Файл қауіпсіздігі үшін MIME type, кеңейтім, файл сигнатурасы және максималды өлшем тексеріледі. Мәтіндік өрістер sanitize логикасынан өтеді. Сонымен қатар жобада rate limit, audit және security helper-лері қарастырылған, бұл production ортада жүйені қорғауға көмектеседі.

Жоба локал ортада Docker арқылы PostgreSQL және Elasticsearch сервистерімен іске қосылады. Production deployment үшін Vercel немесе Render қолдануға болады. Негізгі орта айнымалылары: `DATABASE_URL`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL`, `JWT_SECRET`, `ELASTICSEARCH_URL`, SMTP параметрлері және плагиат тексеру сервисіне арналған параметрлер.

# 4 Еңбекті қорғау және өміртіршілік қауіпсіздігі

## 4.1 Бағдарламашы жұмыс орнына қойылатын талаптар

Бағдарламалық жүйені әзірлеу кезінде негізгі жұмыс құралы - компьютер. Ұзақ уақыт монитор алдында отыру көзге, омыртқаға және жүйке жүйесіне әсер етуі мүмкін. Сондықтан жұмыс орны эргономикалық талаптарға сай ұйымдастырылуы тиіс. Монитор көз деңгейінен сәл төмен орналасуы, орындық арқаға тірек беруі, пернетақта мен тышқан қолдың табиғи қалпын сақтайтындай болуы қажет.

Жұмыс пен демалыс режимін сақтау маңызды. Әр 45-60 минут сайын қысқа үзіліс жасап, көзге арналған жаттығу орындау ұсынылады. Монитор жарықтығы бөлме жарығына сәйкес болуы керек. Тым жарық немесе тым қараңғы экран көз шаршауын арттырады.

## 4.2 Электр және өрт қауіпсіздігі

Компьютер, монитор, роутер және басқа техникалық құрылғылар электр желісіне қосылғандықтан, электр қауіпсіздігі сақталуы тиіс. Зақымдалған кабельдерді қолдануға болмайды, розеткаға шамадан тыс құрылғы жалғау қауіпті. Құрылғыларды ылғал ортада пайдаланбау және желдету саңылауларын жаппау қажет.

Өрт қауіпсіздігі үшін жұмыс орнында жанғыш заттарды электр құрылғыларына жақын қоймау керек. Кабельдер реттеліп, қызып кетпеуі тиіс. Жұмыс аяқталғаннан кейін қажетсіз құрылғыларды өшіру ұсынылады. Кеңседе немесе оқу зертханасында өрт сөндіргіш құралдардың орналасуы белгілі болуы керек.

## 4.3 Жарықтандыру және микроклимат

Жарықтандыру табиғи және жасанды жарықтың үйлесімді болуын талап етеді. Мониторға тікелей күн сәулесі түспегені дұрыс, себебі шағылысу мәтінді оқуды қиындатады. Жасанды жарық біркелкі таралуы және көзге тікелей түспеуі керек.

Микроклимат та жұмыс сапасына әсер етеді. Бөлме температурасы шамамен 20-24 °C аралығында, ауа ылғалдылығы қалыпты деңгейде болғаны жөн. Бөлмені тұрақты желдету, шаңды азайту және техникалық құрылғылардың қызып кетпеуін бақылау жұмыс ортасының қауіпсіздігін арттырады.

# Жобаны іске қосу нұсқаулығы

## Қажетті бағдарламалар

Жобаны локал ортада іске қосу үшін келесі бағдарламалар қажет:

- Node.js 20 немесе одан жоғары нұсқа;
- npm;
- Docker Desktop;
- Git;
- веб-браузер.

## Орнату және іске қосу

Репозиторийді ашқаннан кейін `akademportal` каталогында келесі командалар орындалады:

```bash
npm install --legacy-peer-deps
npm run db:generate
npm run db:push
npm run db:seed
npm run dev
```

Егер Elasticsearch индексін дайындау қажет болса:

```bash
npm run es:index
```

Жоба браузерде келесі мекенжай бойынша ашылады:

```text
http://localhost:3000
```

Seed орындалғаннан кейін бастапқы әкімші аккаунты:

```text
admin@taskin.kz / admin123
```

## Негізгі орта айнымалылары

```env
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/taskin
NEXTAUTH_SECRET=change-me-to-a-long-random-string
NEXTAUTH_URL=http://localhost:3000
JWT_SECRET=
ELASTICSEARCH_URL=http://localhost:9200
```

SMTP және плагиат тексеру интеграциялары production ортада бөлек бапталады.

# Қорытынды

Дипломдық жоба нәтижесінде студенттердің академиялық жұмыстарын орталықтандырылған түрде сақтауға және іздеуге арналған веб-порталдың жұмыс істейтін прототипі әзірленді. Жүйе студент, жетекші және әкімші рөлдерін қолдайды; академиялық жұмыс жүктеу, файл сақтау, метадерек енгізу, рецензиялау, бекіту, қайтару, іздеу, bookmark жасау, хабарлама алу және әкімшілік басқару сияқты негізгі функцияларды қамтиды.

Жобаның архитектурасы Next.js және Prisma негізінде толық стек тәсілмен құрылды. PostgreSQL дерекқоры академиялық жұмыстарды, пайдаланушыларды, рецензияларды, факультеттерді, кафедраларды және хабарламаларды сақтайды. Elasticsearch іздеу сапасын арттырады, ал fallback механизмі жүйенің қосымша сервиссіз де жұмыс істеуін қамтамасыз етеді. NextAuth, bcrypt, Zod және рөлдік authorization helper-лері қауіпсіздік пен дерек сапасын сақтауға көмектеседі.

Жоба практикалық тұрғыдан оқу орны ішінде академиялық материалдарды жүйелеу, жетекші жұмысының тиімділігін арттыру, студенттердің жұмыстарының күйін ашық көрсету және әкімшілік бақылауды жеңілдету үшін пайдалы. Болашақта порталға семантикалық іздеу, толыққанды плагиат тексеру интеграциясы, S3/MinIO object storage, кеңейтілген аналитика, экспорт функциялары және институционалдық репозиторий стандарттарымен үйлесім қосуға болады.
